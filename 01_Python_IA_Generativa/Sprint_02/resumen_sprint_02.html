Colecciones: list, tuple, dict, set

Cuatro estructuras para agrupar datos. Cada una resuelve un problema distinto. Elegir bien ahorra bugs y bucles innecesarios.

La tabla comparativa

TipoSintaxisOrdenMutableDuplicadosPara qué
list[1,2,3]SíSíSíSecuencia ordenada que cambia
tuple(1,2,3)SíNoSíSecuencia fija, inmutable
dict{"k":"v"}Sí (3.7+)SíClaves únicasBuscar por clave
set{1,2,3}NoSíNoElementos únicos, pertenencia

Listas — ordenadas y mutables

notas = [4, 5, 7, 3]
notas.append(10)         # añadir al final
notas.insert(0, 1)        # insertar en posición
notas.remove(3)           # eliminar por valor
notas.pop()               # eliminar y devolver el último
notas.sort()              # ordenar in-place
notas[1:3]                 # slicing
len(notas), max(notas), sum(notas)
[x*2 for x in notas if x > 4]   # comprensión de lista

Tuplas — inmutables

punto = (3, 4)
x, y = punto               # unpacking
# punto[0] = 7  → TypeError: tuple is immutable

Útiles para datos que no deben cambiar (coordenadas, pares clave-valor, retornos múltiples de funciones). Más ligeras que las listas.

Diccionarios — clave-valor

libro = {"titulo": "1984", "autor": "Orwell", "anio": 1949}
libro["titulo"]            # "1984"
libro["paginas"] = 328     # añadir / modificar
libro.get("idioma", "es")  # con valor por defecto
libro.keys(); libro.values(); libro.items()

for k, v in libro.items():
    print(k, v)
Dict como "tabla de handlers": en vez de un if/elif enorme, un dict que mapea clave → función/valor. Más limpio y extensible.

Sets — únicos y rápidos

a = {1, 2, 3, 3, 2}        # {1, 2, 3}  (duplicados fuera)
b = {2, 3, 4}
a | b                       # unión         {1,2,3,4}
a & b                       # intersección  {2,3}
a - b                       # diferencia    {1}
3 in a                     # True  (muy rápido)

Errores típicos

  • Modificar una lista mientras la iteras: comportamiento inesperado.
  • Usar dict[k] cuando la clave no existe: KeyError. Usa dict.get(k, default).
  • Confundir a = b con una copia: en listas y dicts es una referencia al mismo objeto. Usa a.copy().
  • Un set no mantiene orden: no accedas por índice.
  • Las tuplas de un solo elemento llevan coma: (1,), no (1).

Funciones — reutilizar lógica

Una función empaqueta un bloque de código bajo un nombre, con entradas (parámetros) y una salida (return). Es la primera forma de abstracción: dejas de copiar y pegar.

Anatomía

def area_rectangulo(base: float, altura: float = 1.0) -> float:
    """Devuelve el área de un rectángulo."""
    return base * altura

area_rectangulo(5, 3)       # 15.0
area_rectangulo(base=5, altura=3)  # por nombre
area_rectangulo(5)          # 5.0 (altura por defecto)

Scope — dónde vive una variable

x = 10          # global

def f():
    y = 5         # local a f
    print(x)      # ve la global

f()
# print(y)   → NameError (y vive solo dentro de f)
⚠️ Evita variables globales Pasa los datos como parámetros y devuelve el resultado con return. Las funciones puras (sin tocar estado global) son más fáciles de testear y reutilizar.

Argumentos variables

def suma(*numeros, factor=1):     # *args captura varios args
    return sum(numeros) * factor

suma(1, 2, 3)                 # 6
suma(1, 2, 3, factor=10)      # 60

def describir(**kwargs):          # **kwargs captura dict de keyword args
    for k, v in kwargs.items():
        print(f"{k} = {v}")

describir(nombre="Ana", edad=30)

Lambdas y comprensiones

cuadrado = lambda x: x * x       # función anónima
list(map(cuadrado, [1,2,3]))    # [1,4,9]
list(filter(lambda x: x > 2, [1,2,3,4]))  # [3,4]

[x**2 for x in range(5)]            # list comp
{x: x**2 for x in range(5)}         # dict comp
{x**2 for x in [1,-1,2,-2]}         # set comp → {1,4}
Comprensión vs loop: cuando el objetivo es "crear una lista a partir de otra", la comprensión es más legible y rápida.

Errores típicos

  • Olvidar el return: la función devuelve None.
  • Mutar un argumento (lista.append dentro de la función): afecta al caller. Si quieres aislamiento, haz una copia.
  • Argumentos por defecto mutables (def f(x=[])): se comparten entre llamadas. Usa None y crea la lista dentro.
  • Depender de variables globales: hace la función frágil.

OOP: clases, objetos y módulos

Una clase es un molde que agrupa datos (atributos) y el comportamiento que opera sobre esos datos (métodos). Un objeto es una instancia concreta del molde. Es la forma estándar de modelar entidades del mundo real en código.

Anatomía de una clase

class Libro:
    def __init__(self, titulo, autor, anio):
        self.titulo = titulo       # atributos de instancia
        self.autor = autor
        self.anio = anio

    def resumen(self):               # método
        return f"{self.titulo} ({self.autor}, {self.anio})"

l = Libro("1984", "Orwell", 1949)
l.resumen()           # "1984 (Orwell, 1949)"
l.titulo              # "1984"
PiezaQué es
class Libro:Nombre del molde (convención: PascalCase)
__init__Constructor. Corre al hacer Libro(...).
selfReferencia a la instancia actual. Siempre primer parámetro.
self.tituloAtributo de esta instancia concreta.
MétodoFunción definida dentro de la clase; recibe self.

Herencia — extender una clase

class LibroDigital(Libro):      # hereda de Libro
    def __init__(self, titulo, autor, anio, formato):
        super().__init__(titulo, autor, anio)
        self.formato = formato

    def resumen(self):              # sobrescribe (polimorfismo)
        return f"{super().resumen()} [{self.formato}]"

Módulos — organizar código en archivos

# libros.py
class Libro: ...

# main.py
from libros import Libro       # importar lo que necesitas
l = Libro(...)

Un paquete es una carpeta con __init__.py y módulos dentro. Permite agrupar módulos relacionados (p. ej. tienda/clientes.py, tienda/productos.py).

Idea clave Clase = datos + comportamiento que operan sobre esos datos, en el mismo paquete. Si una función solo opera sobre un dict concreto, ese dict quizá quería ser una clase. Si una clase no tiene estado, probablemente quería ser una función.

Errores típicos

  • Olvidar self como primer parámetro de los métodos.
  • Confundir atributos de clase con atributos de instancia (variables declaradas fuera de __init__ se comparten entre todas las instancias).
  • Herencia por herencia: si no se comparte comportamiento real, mejor composición.
  • Importaciones circulares entre módulos: el refactor suele estar en separar en un tercer archivo común.
  • Olvidar raise para lanzar errores desde un método (requisito explícito de la práctica 2).
