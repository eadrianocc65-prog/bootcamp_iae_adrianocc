01 · Colecciones · tuplas

Tuplas: como una lista, pero inmutable

  • Se crean con (). Acceso y slicing como en las listas.
  • Inmutables: no se pueden cambiar. Sirven para datos fijos, como una coordenada.
  • Un solo elemento lleva coma: (5,). Sin coma, (5) es un número.
  • Para «cambiarla»: concatena con + o pásala a lista con list(). Para desempaquetar: x, y = posicion.
  • Lista de tuplas = filas de datos: cada tupla es fija, pero la lista crece.
Votad

Si quitamos el # de posicion[0] = 4, ¿qué pasa?

01 · Colecciones · diccionarios

Diccionarios: cada dato con su nombre

  • Pares clave: valor entre {}. Se accede por clave: heroe["vida"].
  • Asignar a una clave que existe la modifica; a una nueva, la añade. .pop(clave) la elimina.
  • .keys(), .values() y .items(), normalmente dentro de list().
  • Clave que no existe → KeyError. .get(clave, defecto) evita el error.
  • for clave in dic recorre las claves; for clave, valor in dic.items(), las dos.
Antes de ejecutar

¿Qué da heroe["mochila"][1]? ¿En qué línea falla?

01 · Colecciones · sets

Sets: únicos y sin orden · Conversiones

  • {a, b} sin :. Vacío: set(), porque {} es un dict.
  • Sin duplicados y sin índices. .add(), .remove(), in / not in.
  • & en los dos · | en alguno · - en el primero y no en el segundo.
  • Conversiones: list(), tuple(), set() (quita duplicados) y dict(), que necesita pares.
  • list(dic) se queda solo con las claves; list(dic.items()) conserva los valores.

01 · Colecciones · comprensión

Comprensión de listas (y ejercicio)

nueva = []
for x in vieja:
    if filtro(x):
        nueva.append(transformar(x))

nueva = [transformar(x) for x in vieja if filtro(x)]

02 · Funciones · def y return

def, return y lo que se queda dentro

def nombre(entradas):
    operaciones
    return salida
  • Definir no ejecuta nada: la función corre al llamarla. Los paréntesis son obligatorios.
  • return devuelve un valor y termina la función. Sin él, devuelve None. print solo muestra.
  • Puede haber varios return. return a, b devuelve una tupla.
  • Las variables de dentro son locales: fuera no existen (NameError). Si una variable se crea solo dentro de un if que no se cumple → UnboundLocalError.
Antes de ejecutar

02 · Funciones · más allá de def

Lambda, recursión y generadores

HerramientaIdea clave

03 · OOP · clases

La clase es el molde; el objeto, lo que sale de él

  • Objeto = características (atributos) + lo que sabe hacer (métodos). "hola" es un objeto str y .upper(), un método.
  • Crear un objeto a partir de la clase es instanciar. Clases en CamelCase; pass deja una clase vacía.
  • Atributos definidos en la clase: comunes a todos. Se leen y cambian con objeto.atributo.
  • Cambiar o añadir un atributo en un objeto no afecta a los demás.
Votad

¿lyra == bruno? ¿Tiene mascota Bruno?

03 · OOP · constructor

__init__ y self: cada objeto, con sus datos

  • __init__ es el constructor: se ejecuta solo al crear el objeto.
  • self es el propio objeto. Va siempre el primero en el def y no se pasa al llamar.
  • self.nombre = nombre guarda el dato en ese objeto (atributo de instancia). Admite valores por defecto.
  • objeto.__dict__ muestra los atributos propios del objeto.
Pregunta trampa

¿Por qué vida_maxima no sale en __dict__?

03 · OOP · métodos

Métodos: lo que el objeto sabe hacer

  • Funciones dentro de la clase, con self como primer argumento. Se llaman con objeto.metodo().
  • Unos cambian el estado (los atributos) y otros devuelven un valor.
  • La clase también se documenta con una docstring: Clase.__doc__.
