01 · Markdown

Texto plano con unas pocas convenciones

Un lenguaje de marcado ligero: escribes texto normal con símbolos como #, * o `, y la herramienta lo convierte en títulos, listas, enlaces o código resaltado.

  • Simple y legible en crudo: se entiende incluso sin renderizar.
  • Versionable con Git, a diferencia de un documento de Word.
  • El estándar de facto es GFM (GitHub Flavored Markdown).
¿Por qué en IA?Los modelos de IA entienden muy bien Markdown. Usarlo en tus prompts te ayuda a dar instrucciones más precisas y estructuradas.

El mismo texto, en crudo y renderizado

## Playlist del lunes
- **Neón**: 3:30
- *Marea*: 3:05
- [ ] Añadir más temas

Playlist del lunes

• Neón: 3:30
• Marea: 3:05
☐ Añadir más temas

2

3

4

Editar

Doble clic sobre el texto para volver al modo edición.

¿Dónde lo vas a usar?

  • Celdas de Jupyter y Colab: enunciado, contexto y conclusiones junto al código.
  • README y documentación en GitHub.
  • Issues, pull requests, foros… y prompts.

Las celdas de código siguen siendo código. Markdown también acepta HTML dentro de la celda.

01 · Markdown

Errores típicos y buenas prácticas

EscribesProblema
** negrita **Con espacios junto a los asteriscos no se aplica la negrita.
#TítuloDeja un espacio después de #.
# … y luego ### …No te saltes niveles de título: rompe la jerarquía y la accesibilidad.
Dos líneas seguidasSe juntan en un párrafo. Usa línea en blanco o dos espacios al final.
* o _ sueltosActivan cursiva sin querer: escápalos con \.
OjoEl mismo Markdown puede verse distinto en Jupyter, VSCode y GitHub. Algunas extensiones de GFM, como las notas al pie, no siempre funcionan en Jupyter.
01 · Markdown · un adelanto

Markdown como especificación: la idea del Spec-Driven Development

Antes de pedirle código a la IA, se escribe en Markdown qué tiene que hacer el programa. Esa spec pasa a ser la referencia común para ti y para la IA.

  • Todo es Markdown: títulos, listas, tablas y listas de tareas. Exactamente lo que acabamos de ver.
  • No es para todo: para un cambio pequeño, una spec larga sobra.
Hoy, solo la ideaEsta spec la programamos en el bloque 03 con if/elif/else.

02 · Python I · variables

    
Cómo (no) nombrar una variable

    

      

        
    
          
  • minúsculas_con_guion_bajo y nombres descriptivos, pero no larguísimos.
    • 
          
  • Sin espacios y sin empezar por un número: top_10 sí, 10_top no.
    • 
          
  • Distingue mayúsculas: playlist y Playlist son variables distintas.
    • 
          
  • No uses palabras reservadas (class, for, if…).
    • 
          
  • Evita ñ y tildes en los nombres.
    • 
          
  • Las constantes van en MAYÚSCULAS: MAX_CANCIONES = 500.
    •

FormaDetalle

03 · Flujos · sintaxis

    
Dos puntos e indentación: así se marcan los bloques

    

      

        
Otros lenguajes usan llaves { }. Python usa la indentación: 4 espacios (o un tabulador).

        
    
          
  • if, for, while, try, funciones y clases terminan en :.
    • 
          
  • Todo lo indentado debajo pertenece a ese bloque. Lo que vuelve a la izquierda queda fuera.
    • 
          
  • Un if dentro de un for lleva doble indentación.
    • 
        

        Arréglalo en directo
        
Este código falla. Arréglalo y después mueve el último print dentro del for: ¿qué cambia?

      

      


      

    

  






  

    
03 · Flujos · condicionales

    
if / elif / else: etiquetar por ritmo

    

      

        
    
          
  • Las condiciones se evalúan en orden.
    • 
          
  • Solo se ejecuta el primer bloque cuya condición es True; el resto se ignora.
    • 
          
  • Por eso basta con bpm < 120: si llegamos ahí, ya sabemos que el BPM es mayor o igual que 90.
    • 
          
  • else recoge todo lo demás. Es opcional.
    • 
        

        Ejercicio
        
Es la spec del bloque 01. ¿Qué pasa con bpm = 400 o -5? Añade el caso "BPM no válido".

      

      


      

    

  






  

    
03 · Flujos · bucles

    
Bucle for: repetir para cada elemento

    

      

        
Sin bucle tendríamos que escribir un if por cada canción. Con for, el mismo código sirve para 4 canciones o para 4000.

        
for variable in iterable: En cada vuelta, variable toma el siguiente valor.

        
    
          
  • Un iterable es una colección que se puede recorrer: listas, str, range()…
    • 
          
  • Truco habitual: un acumulador (total = 0 antes del bucle y se suma dentro).
    • 
        

      

      


      

    

  






  

    
03 · Flujos · bucles

    
range(inicio, fin, paso)

    

      

        
    
          
  • Genera números desde inicio hasta fin, sin incluir el fin.
    • 
          
  • range(5) empieza en 0. El paso puede ser negativo.
    • 
          
  • range(len(lista)) recorre las posiciones de una lista.
    • 
        

        
Buena prácticaNo escribas a mano el tamaño en el range: si la lista cambia, fallará (IndexError) o se dejará elementos sin recorrer. Usa len().

¿Qué números da range(3, 12, 4)?

03 · Flujos · bucles

    
Bucle while: repetir mientras se cumpla una condición

    

      

        

          
1
Declara la variable de ejecución fuera del bucle.

          
2
Define la condición que lo mantiene vivo.

          
3
Actualiza la variable en cada vuelta.

        

        
Bucle infinitoSi olvidas el paso 3, nunca termina. En Jupyter o Colab: botón de stop (interrumpir el kernel).

        Ejercicio

03 · Flujos · bucles

    
break, continue y pass

    

      

        
break
Sale del bucle. Por ejemplo, para cuando ya has encontrado lo que buscabas.

        
continue
Salta al siguiente elemento sin ejecutar el resto del código de esa vuelta.

        
pass
No hace nada. Sirve para ocupar un hueco donde Python exige código.

        Predice
        
¿Qué números imprime cada bucle?

      

      


      

    

  






  

    
03 · Flujos · errores

    
try / except: que un dato malo no pare el programa

    

      

        
    
          
  • try: el código que puede fallar.
    • 
          
  • except TipoDeError: qué hacer si falla con ese error. Puedes encadenar varios.
    • 
          
  • except Exception as e: captura cualquier error y guarda su mensaje en e.
    • 
          
  • finally: se ejecuta siempre, haya error o no.
    • 
        

        Pregunta al grupo
